Synthetic Data Vault: генерация сложных синтетических данных















Synthetic Data Vault (SDV) — это целый фреймворк, предназначенная для создания синтетических данных, которые не просто выглядят правдоподобно, а сохраняют статистические свойства и взаимосвязи реальных данных. SDV обучается на ваших данных и создает синтетические наборы, отражающие корреляции, распределения и структуру исходной информации. При этом инструмент позволяет генерировать не только отдельные столбцы данных, но и целые таблицы, связанные между собой отношениями, временные ряды и даже графовые данные.



Как работает?



В основе SDV лежат инструменты моделирования. Вместо простого случайного комбинирования шаблонов, SDV сначала анализирует реальные данные, выявляет их структуру, статистические распределения, корреляции и зависимости. На основе этого анализа SDV обучает генеративные модели, которые затем используются для создания синтетических данных.



Спектр генеративных моделей достаточно большой, вот некоторые из них:











Gaussian Copula. Статистическая модель, хорошо подходящая для генерации табличных данных со сложными корреляциями. Она основана на идее преобразования данных к нормальному распределению и моделирования корреляций в этом пространстве.







CTGAN (Conditional Tabular GAN). Модель, основанная на генеративно-состязательных сетях (GANs), специально разработана для генерации табличных данных с учетом категориальных и непрерывных признаков. ных распределений и модальностей.







TVAE (Tabular Variational Autoencoder). Еще одна модель на основе глубокого обучения, использующая вариационные автоэнкодеры для генерации табличных данных. TVAE хорошо справляется с моделированием сложных нелинейных зависимостей.







Модели временных рядов. SDV предлагает набор моделей, которые "клонируют" временные ряды, воспроизводя их временную динамику и статистические свойства.







И многие другие модели для разных типов данных и задач.



SDV также позволяет сохранять обученные модели в специальном "хранилище" (Vault). Это позволяет их переиспользовать без необходимости повторного обучения, что сэкономит ресурсы.

Пример 2: Генерация синтетических финансовых транзакций для обнаружения мошенничества



Представим, что нам нужно обучить модель для обнаружения мошеннических финансовых транзакций. Реальные данные о мошенничестве редки и чувствительны. Тот же Faker может сгенерировать фейковые транзакции, но они будут слишком простыми и не отразят сложную временную динамику и взаимосвязи между транзакциями, характерные для реального мира финансов. А SDV позволят решить эту проблему, смоделировав временные ряды транзакций и связи между ними.  







В этом примере мы использовали модель PAR (Probabilistic Autoregressive Model) из SDV, специально разработанную для генерации синтетических временных рядов. Модель учитывает временные зависимости в транзакциях каждого пользователя, а также статистические свойства признаков транзакций. Сгенерированные синтетические данные гораздо лучше подходят для обучения моделей обнаружения мошенничества, чем простые фейковые данные.  



Пример 3: Синтез медицинских данных с учетом коморбидности и сложных взаимосвязей



В разделе про Faker мы рассматривали кейс неудачной генерации синтетики для медклассификатора. SDV позволяет избежать таких ошибок, моделируя сложные взаимосвязи между диагнозами, симптомами, анализами и другими медицинскими показателями.  







Здесь используется модель HMA (Hierarchical Multi-table model), которая специально разработана для генерации синтетических связанных таблиц. HMA учитывает иерархическую структуру данных, корреляции внутри таблиц и связи между таблицами. Это позволяет генерировать гораздо более реалистичные медицинские данные, чем просто набор изолированных признаков.  



Пример 4:  Генерация синтетических данных для графовых нейронных сетей (GNN)  



SDV не ограничивается только табличными данными. Он также позволяет генерировать синтетические графовые данные, и это можно использовать для моделирования социальных сетей, сетей взаимодействия устройств IoT, биологических сетей и других сложных систем.







 В этом примере мы использовали модель KGCN (Knowledge Graph Completion Network), предназначенную для генерации синтетических графов. KGCN изучает структуру реального графа (распределение степеней узлов, кластеризацию, пути и другие характеристики) и генерирует новый граф, максимально похожий на оригинал по структуре и свойствам. 



 Преимущества и недостатки SDV



➕:











Разнообразие форматов для генерации. SDV позволяет генерировать не только простые табличные данные, но и сложные структурированные данные, временные ряды и графы.  







Моделирование зависимостей. SDV умеет учитывать зависимости между признаками, временные зависимости и иерархические связи в данных, что критически важно для реалистичности синтетики.  







Разнообразие моделей для разных типов данных. SDV предлагает широкий выбор генеративных моделей, оптимизированных под разные типы данных и задачи, позволяя выбрать наиболее подходящий инструмент для каждого случая.







Интеграция с другими инструментами. SDV легко интегрируется с pandas для обработки данных и может быть встроен в пайплайны машинного обучения или ETL-процессы.



➖:











Более высокий порог входа, чем у ранее рассмотренных инструментов. SDV требует более глубокого понимания концепций моделирования данных и выбора подходящих моделей. Процесс освоения может быть не самым простым.







Более ресурсоемкий процесс обучения моделей. Обучение моделей SDV, особенно сложных для больших объемов данных, может потребовать значительных вычислительных ресурсов и времени.







Может быть избыточен для простых задач. Для простых задач, где достаточно генерации базовых типов данных, использование SDV может быть избыточным и неоправданно сложным.



Когда стоит использовать?



 SDV – очень хороший выбор, когда перед нами стоят сложные задачи, требующие:











Высокой реалистичности и статистического соответствия синтетики реальным данным.







Генерации сложных структурированных данных, временных рядов, связанных данных, графовых данных.







Моделирования зависимостей и сложных сценариев.







Задач, где качество синтетических данных критически важно для обучения моделей или имитации бизнес-процессов.



А в каких случаях этот инструмент не очень подойдет?











Небольшие наборы данных с низкой вариативности (SDV может начать просто копировать исходные объекты).







Есть сложные текстовые поля (SDV не предназначен для генерации качественных текстов и будет выдавать бессмыслицу)







В данных есть сверхредкие события и аномалии (из-за сильного дисбаланса подобные редкие кейсы SDV может вообще упустить).







Задач, где качество синтетических данных критически важно для обучения моделей или имитации бизнес-процессов.

import pandas as pd
import numpy as np
import networkx as nx
import matplotlib.pyplot as plt
from sdv.multi_table import HMASynthesizer
from sdv.metadata import MultiTableMetadata

# Step 1: Load and prepare data
# Simulated data (replace with real BioGRID data loading if available)
nodes = pd.DataFrame({
    'protein_id': [f'P{i}' for i in range(5000)],
    'molecular_weight': np.random.uniform(20, 200, 5000),  # Mass in kDa
    'function': np.random.choice(['Signaling', 'Metabolism', 'Cancer', 'Other'], 5000, p=[0.3, 0.3, 0.2, 0.2])
})

edges = pd.DataFrame({
    'source': np.random.choice(nodes['protein_id'], 50000),
    'target': np.random.choice(nodes['protein_id'], 50000),
    'interaction_type': np.random.choice(['Physical', 'Genetic'], 50000),
    'confidence': np.random.uniform(0.5, 1.0, 50000)  # Experimental confidence
})

# Step 2: Set up metadata for SDV
metadata = MultiTableMetadata()

# Detect metadata from the data dictionary
data = {'proteins': nodes, 'interactions': edges}
metadata.detect_from_dataframes(data)

# Update column types for 'proteins' table
metadata.update_column(
    table_name='proteins',
    column_name='protein_id',
    sdtype='id'
)
metadata.set_primary_key(
    table_name='proteins',
    column_name='protein_id'
)

# Update column types for 'interactions' table
metadata.update_column(
    table_name='interactions',
    column_name='source',
    sdtype='id'
)
metadata.update_column(
    table_name='interactions',
    column_name='target',
    sdtype='id'
)

# Define relationships
metadata.add_relationship(
    parent_table_name='proteins',
    child_table_name='interactions',
    parent_primary_key='protein_id',  # Added required argument
    child_foreign_key='source'
)
metadata.add_relationship(
    parent_table_name='proteins',
    child_table_name='interactions',
    parent_primary_key='protein_id',  # Added required argument
    child_foreign_key='target'
)

# Step 3: Train the multi-table synthesizer
synthesizer = HMASynthesizer(metadata)
synthesizer.fit(data)

# Step 4: Conditional generation of synthetic graph
# Condition: 30% of nodes should have function "Cancer"
conditions = {
    'proteins': pd.DataFrame({
        'protein_id': [f'P{i}' for i in range(1500)],
        'function': ['Cancer'] * 1500
    })
}
synthetic_data = synthesizer.sample(
    num_rows={'proteins': 5000, 'interactions': 50000},
    conditions=conditions
)

# Extract synthetic data
synthetic_nodes = synthetic_data['proteins']
synthetic_edges = synthetic_data['interactions']

# Step 5: Visualization (subgraphs for speed)
def plot_subgraph(edges, title):
    G = nx.from_pandas_edgelist(edges.head(200), 'source', 'target')
    plt.figure(figsize=(10, 8))
    nx.draw(G, node_size=50, edge_color='blue', alpha=0.5, with_labels=False)
    plt.title(title)
    plt.show()

plot_subgraph(edges, 'Real PPI Graph (Subgraph)')
plot_subgraph(synthetic_edges, 'Synthetic PPI Graph (Subgraph)')

# Step 6: Compare metrics
def advanced_metrics(edges):
    G = nx.from_pandas_edgelist(edges, 'source', 'target')
    degrees = [d for n, d in G.degree()]
    betweenness = nx.betweenness_centrality(G, k=100)  # Limited for speed
    return {
        'Average Degree': np.mean(degrees),
        'Average Betweenness Centrality': np.mean(list(betweenness.values())),
        'Clustering Coefficient': nx.average_clustering(G),
        'Number of Triangles': sum(nx.triangles(G).values()) / 3
    }

real_metrics = advanced_metrics(edges)
synthetic_metrics = advanced_metrics(synthetic_edges)

print("Real Graph Metrics:", real_metrics)
print("Synthetic Graph Metrics:", synthetic_metrics)
